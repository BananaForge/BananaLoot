# BananaLoot Changelog

## v3.52 (vs. v3.51)

- **New:** raidres.top **CSV export** can be imported (header `ID,Item,Boss,Attendee,Class,Specialization,Comment,Date (GMT)`, one reservation per line, quoted fields supported). Paste the CSV into the import window and click "Import" - non-BananaLoot text is detected automatically and goes the raidres.top way (the old Base64/JSON export still works, the "raidres.top" button too). Item names come from the file. The CSV carries no SR+ values, so SR+ stays as it is locally.
- **Changed:** Wording: the raid setup button says "Import SR (raidres.top)" instead of "raid request link", and the hints explain the steps (open the page in the browser, copy the export, paste it into the import window).

## v3.51 (vs. v3.50)

- **Changed:** Raid lead boss explanations are no longer posted to raid chat. Targeting a boss (or the "send" buttons in the raid lead window) now sends them as an addon message to BananaLoot Raider, which shows each player a small window with only the explanation for their role. Edited texts are sent along and stored by Raider. Welcome/trash/closing messages still go to chat.

## v3.50 (vs. v3.49)

- **Changed:** The "ARF" wording is gone from everything players see: the raid chat announcement now says "Frei-Roll" / "Open Roll", as do the roll popup mode and tooltips. The `/bl arf` command still works.

## v3.49 (vs. v3.48)

- **New:** Button "Assign" on every loot item (except Hard Reserve): choose any raid member from a list, then confirm twice ("Award X to Y?" and "SECOND CONFIRMATION") before the item is awarded manually.
- **New:** `docs/CHAT_TEXTE.md` lists every text BananaLoot posts to raid/party chat, whispers and the world channel, with the event that triggers it.

## v3.48 (vs. v3.47)

- **New:** Check box "BR" next to "Raid Roll" and "Auto" on every loot item: puts the item on the bank character list (bank reserve). On the next auto run or drop it goes to the BR looter automatically (also when auto mode is already running). Hard Reserve items cannot be checked; BR replaces the Raid Roll entry.
- **New:** Small "DE" / "EN" buttons at the top right next to the close cross of the main window and the loot window (the Raider history too): one click switches the language immediately.
- **New:** The LFM assistant text is now editable right in the assistant (add what cannot be selected, choose the line yourself) with a live 255 character counter (links counted as in chat; turns red when too long, applying is refused). A new selection regenerates the text.
- **New:** Award messages also carry a kill number so BananaLoot Raider keeps same-named mobs killed one after another as separate groups.

## v3.47 (vs. v3.46)

- **New:** Award messages now carry the source of the loot (boss/mob: dead target, otherwise the last mob that died). BananaLoot Raider uses it to group its loot history per boss/mob.

## v3.46 (vs. v3.45)

- **New:** Second check box "Auto" on every item of the loot window. Checked (default) = auto mode handles the item. Unchecked = you award it manually; auto mode skips it. Hard Reserve items are always manual. When auto mode finishes it now reports how many items are still open for manual awarding.
- **Fix:** The test window status was confusing ("Items in loot window 3 / 16" although everything was processed). It now reads "Awarded: X of Y | still in loot window: Z" (the remaining ones are Hard Reserve / no-roll items you award by hand).

## v3.45 (vs. v3.44)

- **New:** Check box "Raid Roll" on every item of the loot window. Checked = the item is on the Raid Roll list (set from the start, the box is already checked). If something drops that you do not want to roll, check the box: the item is raffled among the raid without a roll when you start auto mode, or immediately when auto mode reaches it if it is already running. Unchecking takes it off the list again. Hard Reserve items cannot be checked. The tick only changes the running list; at the next raid start the raid setup tidies the list for that raid's items again.

## v3.44 (vs. v3.43)

- **New:** LFM assistant: the generated text is now always **English** (the world channel is English), regardless of the addon language; only the buttons follow your language. The raid's Hard Reserve items are posted as **clickable item links** in the world channel (the text shows `[Item]`, the links are inserted when posting). The length is counted with the links (a link costs about 44 more characters), so fewer items fit; the rest is shown as "+N".
- **Fixed:** A stray line was visible in the LFM text field (left over from the single-line input template); the field now has its own frame.
- **Changed:** The confirmation dialogs of BananaLoot (end raid, raise SR+, delete a raid ...) have a dark background instead of the see-through Blizzard one.
- **Changed:** Loot window redesigned: every item sits in its own frame, the three buttons (Start Roll, Open Roll, Manage) are on the line of the item name, and each text line (reservers, status, winner) has its own position, so nothing overlaps any more. "ARF" is now called "Open Roll" (German: "Frei-Roll", ARF = All Rolls Free: an open roll for everyone, SR suspended) and all buttons have tooltips. The window is wider (600).
- **New:** Test run with BananaLoot Raider: if BananaLoot Raider is installed, every roll of the test shows the Raider's roll popup (roll along with MS/OS/TM), the made-up players' rolls and the winner appear in it, and awards fill the Raider's loot history. Test run only; nothing is sent over the network. Auto mode rolls and awards all test items as before.

## v3.43 (vs. v3.42)

- **New:** The version number is shown in the title of the main window ("BananaLoot - SoftReserve / SR+ v3.43") and in the load message. `/bl version` shows your version and asks the group who has which version of BananaLoot and BananaLoot Raider (older versions are flagged); the Hand over lead list shows the version of each player. Rule: every change raises the version (TOC + `BananaLoot.VERSION` + CHANGELOG heading); `tools/run_tests.sh` fails if the CHANGELOG has no heading for the current version.

- **Changed:** All windows now have a dark, nearly opaque background (easier to read, no text of other windows showing through) and are brought fully to the front when clicked or opened. Layers unified: SR window, loot window, roll-sync popup and test mode are `HIGH`, every other window is `DIALOG` (`BananaLootTheme.lua`).
- **New:** LFM assistant. The LFM window has a new "Build text..." button: pick a prepared raid and what you are looking for (Tanks / Healers / DPS as role buttons, whole classes, or single specs such as Warrior (Protection) or Druid (Bear)) and the world channel text is generated, including the raid's Hard Reserve items, with a live preview and the 255 character limit handled. "Use text and start LFM" posts it right away and then at the set interval.
- **New:** Auto mode now runs the whole chest by itself: after a roll it waits 3 seconds, awards the winner automatically and starts the next roll (Hard Reserve items are never awarded automatically; if an award fails, auto mode pauses). New option Options > Automation > "Auto mode awards automatically" (default: on); switched off, auto mode waits for "Award" after every winner as before.
- **Fixed:** The raid timer at the bottom of the main window was covered by the "Hand over lead" button; the timer now sits at the bottom left. A long raid name no longer bursts the "Select raid" button in the side menu: it is shortened with "..." (the tooltip shows the full name).
- **New:** The test run uses the new raid structure. "Start test run" asks for one of five test raids (Molten Core, Blackwing Lair, AQ40 with 2 SR per player, Naxxramas, UBRS), each prepared with 2 Hard Reserve, 1 Bank Reserve, 2 Raid Roll items and SR of 10 made-up players. The chosen raid is started the real way: lists are set, the SR show up in the main window and the loot drops into the loot window (about 16 slots, including a Bank Reserve and two Raid Roll items that are awarded automatically). All five test raids appear in the raid list during the test. Prepared raids, templates, the running raid, the SR lock and the SR limit are backed up and restored afterwards (also after a /reload or crash).
- **New:** Every item has information. `BananaLootItemInfoExtra.lua` (1,527 items from AtlasLoot, generated by `tools/gen_item_info.py`) adds name, quality and icon for instance, set, PvP, world boss and world event loot that the item database lacked. The loot window no longer shows "Item #22520" or a question mark for such items. If the client has no tooltip for an item, BananaLoot builds one locally from the item database (item level, slot, armor/weapon damage, stats).
- **Changed:** Item preloading remembers its requests for 3 days (no more "Loading 180 unknown items" on every zone change/login), reports at the end how many items the client now knows and how many the server did not answer, and can preload ALL instances in the background after login (`/bl prefetch all`, `/bl prefetch auto on|off`, default: on). With BananaLoot Raider installed only BananaLoot preloads.
- **Fixed:** The main window headline showed the name of an old saved raid ("1234") when no prepared raid was selected; it now shows "Select raid...".
- **New:** Bank Reserve list in the raid preparation (4th list next to Hard Reserve, Raid Roll and the SR hint): tick the items that automatically go to the Bank Reserve looter. Applied at the raid start like the other lists, stored in the prepared raid and the template; raiders see these items locked in the SR window. An item is on exactly one list.
- **New:** Hand over lead now lists only raid/party members who have BananaLoot (detected via a short ping, "Show all players" as fallback). The chosen player becomes raid leader immediately and receives the prepared raid automatically by code, no code entry needed.
- **New:** "Pick from raid" in Set Disenchanter / Set BR Looter: choose a player of the raid or party, or still type a name by hand.
- **New:** Small draggable GL/ML button that is always visible (`/bl mini` shows or hides it); one click switches group loot / master loot.
- **New:** BananaLoot Raider finds the active raid of your group on its own and connects with the raid code automatically (only via raid or party chat, never guild; a code typed by hand is kept).
- **Changed:** Main window tidied: the RL/HR/BR/? buttons moved into the control row, the side menu only holds Select Raid, Start Raid, Options, LFM, Set Disenchanter, Set BR Looter and Auto ML. Export, Import, Save Raid and Load Raid are now under Options > Management; the "Raid Setup" button is gone (use `/bl setup`). Several buttons were widened so the text fits.
- **New:** Raid code. Every prepared raid gets a code (e.g. `MC-7K3Q`). Raiders enter it in BananaLoot Raider, pick their SR items from the raid's loot (icons, tooltips, search, quality filter) and send them. The SR travels as an addon message through the raid chat (without a raid: party, otherwise guild), so it works before the raid and without whispers. The loot master and every stand-in who loaded the raid by code receive it; the raider gets a confirmation (items accepted, skipped Hard Reserve / Raid Roll items, limit, closed). In the raid list: "Post code" (posts the code in raid/party/guild chat), "SR open/closed" (open or close submissions before the start) and "Load code" for a stand-in (`/bl join <code>`), who then gets the full raid: Hard Reserve, Raid Roll, name and all SR so far.
- **New:** SR sent via the raid code show up in the main window right away for the selected raid (before the raid starts). Switching the selected raid swaps the displayed SR.
- **Changed:** "SR open/closed" in the raid list and the "Open/Locked" button in the main window are now the same switch for the selected or running raid: toggling one updates the other (and the raiders see the new state).
- **New:** Starting a prepared raid takes over the SR collected via the raid code and locks the SR list. The lock button in the main window reopens it (e.g. before a certain boss); SR sent via the code then go straight into the reservations. The raider sees open/closed live.
- **New:** "Hand over lead" button in the main window: lists the other raid/party members; the chosen player becomes raid leader (and loot master, if you were the loot master). Requires being the raid/party leader.
- **New:** Prepare raids ahead of time. Options > Management > "New Raid" now opens the raid preparation: pick the raid (MC, Onyxia, BWL, ZG, AQ20, AQ40, Naxxramas, Emerald Sanctum, Lower/Upper Karazhan Halls, Timbermaw Hold, UBRS), then (1) Hard Reserve: tick the items of that raid's loot tables (grouped by boss, icon, quality color, item tooltip on mouse-over, search field, per-boss select all/none), (2) Soft Reserve: reminder to collect SR by whisper or import the raid request link, (3) Raid Roll: tick the items that are raid-rolled from the start. Then name the raid (default "<Raid> <date>") and save it. You can prepare as many raids as you like (e.g. "Molten Core 13.05.28", "BWL 05.10.18").
- **New:** Quality filter in the item pick lists: White / Green / Blue / Epic / Orange (multiple allowed). "All" / "None" only affect the visible items, so "Green" + "All" puts all green items on the Raid Roll list in one click.
- **New:** Prepared raids in the main window: the headline above the SR list shows the selected (or running) raid and opens the list of prepared raids (select, edit, delete). "Start raid" starts the selected raid and sets its Hard Reserve and Raid Roll lists. "Start without preparation" is still available in that list.
- **New:** Per raid type, the last prepared selection is offered as a template when you prepare the next raid of the same type.
- **New:** Raid setup "Drops" tab (running raid): lists the items that dropped. Rolled one normally by mistake? One click makes it a Raid Roll item from now on and also puts it into the prepared raid and the template for the next run. Also reachable via the "Raid Setup" button in the SR side menu and `/bl setup`. Data: `BananaLootRaidLoot.lua` (from AtlasLoot Turtle WoW Edition, used with the developer's permission, generated by `tools/gen_raid_loot.py`).
- **Changed:** "New Raid" in the options no longer clears the reservations; use `/bl reset` for that. "Start raid" no longer asks for a raid but starts the selected prepared one.
- **Changed:** The raid of the started prepared raid is used for the raid lead announcements instead of the zone detection.
- **New:** Item preloading per instance. When you enter a dungeon or raid, BananaLoot asks the server (slowly, 4 items per second, via an invisible tooltip) for every item that can drop there and that your client doesn't know yet. The Blizzard roll window then shows icon and tooltip instead of a question mark. Purely local: no addon messages, the Roll-Sync protocol is unchanged. Data: `BananaLootZoneLoot.lua` (from AtlasLoot Turtle WoW Edition, used with the developer's permission, generated by `tools/gen_zone_loot.py`). Commands: `/bl prefetch` (run now for the current zone), `/bl prefetch on|off`. German zone names are not verified in-game; if a zone isn't recognized, `/bl prefetch` says "No loot data for '<zone>'".

## v3.42 (vs. v3.37)

Note: v3.38 to v3.41 were not published as separate releases, so this entry includes their changes.

- **New:** Raid roll list: a third item list next to Hard Reserve and Bank Reserve. Items on it are rolled automatically the moment the loot window opens (also in auto mode): the winner is picked randomly among raid members who are in the raid AND reachable via master loot, announced in raid/party chat, assigned and logged as "Raid Roll". Multiple copies are rolled one by one; if an assignment fails, the item stays in the loot window. Managed via the new "RL" button in the SR window, `/bl raidroll [Item][Item]...` and `/bl raidroll remove [Item]`. The list is part of the normal export/import string. Priority when an item is on several lists: Bank Reserve > Hard Reserve > Raid roll; adding an item to one list removes it from the other two.
- **New:** Manage window: after "Add" a choice appears. "This drop only" adds the player as a temporary reserver (can roll and be picked as winner, but replaces no SR, has no SR+, is not raised at raid end and is hidden in the SR window and exports). "Add to SR list" keeps the previous behaviour. Temporary entries are removed when the item is awarded or skipped, or when the reservation is deleted.
- **New:** Name mapping manager: lists all saved mappings (import name -> ingame name) with a Remove button per entry. Open it via Options ("Name mappings"), the "Manage mappings" button in the match-names window, or `/bl alias list`.
- **New:** Removing a mapping (manager or `/bl alias del <name>`) now moves the reservations and SR+ values it transferred back to the import name. Mappings created with older versions have no record of this: only the mapping is removed, and a new raidres.top import restores the SR.
- **New:** raidres.top import without a group: all imported names are checked in a window with a text field per name. OK confirms the name, a changed name is saved as a mapping for future imports.
- **New:** Confirmation prompt when a different name is matched to your own character.
- **New:** Shift+left-click on an item icon (SR window, loot window, roll-sync popup) inserts the item link into the open chat edit box.
- **Changed:** Side menu of the SR window reworked: wider panel, uniform button size, more spacing and grouped sections with separators.
- **Changed:** The manual "Raid Roll" button in the Manage window now also only picks from raid members reachable via master loot.
- **Fixed:** Game freeze/crash when opening loot as master looter in a raid. The routine that removes reservations of players who are no longer in the raid (PruneAbsentReservations) could loop forever on inconsistent reservation data. It now collects the absent names first, removes them in a fixed-length loop and cleans up inconsistent entries directly.
- **Technical:** New SavedVariables field `raidRolls`; new export record type `R`. Alias entries now store which reservations and SR+ values they moved (`moved`, `plus`).

## v3.37 (vs. v3.36)

- **Changed:** The roll instructions in chat, the help text, README and manual now say `/roll 99` (Off-Spec) and `/roll 98` (Transmog) instead of `/roll 1 99` and `/roll 1 98`. Detection is unchanged, since both forms produce the same 1-99 / 1-98 roll.

## v3.36 (vs. v3.35)

- **New:** Default raid lead announcements for all 50 bosses that had none: Molten Core (10), Onyxia, Blackwing Lair (8), Zul'Gurub (10), Naxxramas (15) and the six world bosses (Azuregos, Lord Kazzak and the four Emerald Dragons). Each boss gets a short message 1 (tank/DD/healer hints plus curse, poison and disease notes); message 2 stays empty. Everything remains editable in the raid lead window and your own texts always take priority. The mechanics are written from general Vanilla knowledge, so check them against your raid strategy (and against Turtle WoW changes) before relying on them.

## v3.35 (vs. v3.34)

- **New:** Disenchanter: new side-menu button "Set Disenchanter" in the SR window. If nobody rolled on an item, the loot window now shows a "Disenchant" button instead of "Award". Clicking it awards the item directly to the set disenchanter without another roll (also in auto mode). The award goes through the normal award path (loot log and shared history category "Disenchant", roll-sync broadcast, queued if the loot window is closed) and is announced in raid/party chat. If no disenchanter is set, a chat hint is shown.
- **New:** BR looter: new side-menu button "Set BR Looter". Bank Reserve items are now awarded automatically to the set player instead of the loot master. Without a setting the loot master still receives them, as before.
- **New:** The winner is now shown on its own line in every loot window row ("Winner: Name" in class color, for multi-drops the next unawarded winner; "Disenchanter: Name" for disenchant). Rows are taller to make room for it.
- **New:** Side-menu button "Auto ML on boss: On/Off" toggles the automatic switch to Master Loot when targeting a raid boss (default on, same setting as in Options > Automation).
- **New:** Optional test raid Upper Blackrock Spire (UBRS): new option "Enable UBRS as test raid" (Options > Management, below the raid lead switch, default off, independent of the raid lead switch). When on, the UBRS bosses (Pyroguard Emberseer, Solakar Flamewreath, Goraluk Anvilcrack, Jed Runewatcher, Rend Blackhand and Gyth, The Beast, General Drakkisath) trigger the raid lead announcements and the auto Master Loot, and a trash note about the Blackhand Dreadweavers' curses is sent after the welcome message on Start Raid. When off, UBRS is ignored everywhere. Raids can now carry default welcome/trash texts in the boss data.
- **Fixed:** Stratholme is excluded from boss detection. Bosses there that share a name with Naxxramas bosses (e.g. Baron Rivendare) no longer force Master Loot or trigger Naxxramas announcements.
- **Changed:** Test mode now sets a fake disenchanter and BR looter during the run (your real settings are backed up and restored) and drops one Bank Reserve item.

## v3.34 (vs. v3.32)

Note: v3.33 was never published, so this entry includes its changes.

- **New:** Item database replaced: the AtlasLoot-derived data is gone. BananaLootItemDB.lua now contains 14,230 items (name, quality, icon and further attributes) from Bananaforge Luminar. THIRD_PARTY_NOTICES.md and the README were updated accordingly.
- **Fixed:** Item icons were missing in the SR window, the loot window and the roll-sync popup. They now come from the new item database first, so they appear immediately, even for items the client has never seen. Items without an icon in the data keep the question mark.
- **New:** raidres.top import now reconciles per player instead of wiping: an item the raider already has on SR stays untouched and keeps its SR+; an old item that is missing from the import is removed and its SR+ is reset; a new item is reserved (SR+ only if raidres.top supplies one). Players who are not part of the import are never touched, and a player whose import items are all hard-reserved keeps the old SR. Duplicate entries for the same item are ignored.
- **New:** Whispers after a raidres.top import: affected raiders are told when their SR was overwritten ("Your SR reservation [A] was overwritten by an external Raidres.top import. Now on SR: [B] with SR+ X.") or removed. Whispers are throttled to one per second, fall back to plain item names if the text would exceed 255 characters, and players who are not in the raid/group are listed in your chat instead.
- **New:** Option "Raidres.top SR+ takes priority" (Options > General, default off). Off: your local SR+ is kept for items that are already reserved. On: an SR+ value greater than 0 from raidres.top overwrites the local SR+.
- **New:** Name mapping for raiders whose Discord/raidres.top name differs from their in-game name: a "Match names" window opens automatically after an import when reserved names are not in the raid/group (also via /bl alias). Each name offers a suggestion (case, umlaut/accent and small typo matching, never applied automatically) or a pick from the current raid list. A mapping transfers existing reservations and SR+ immediately and is applied automatically to every future import. Commands: /bl alias, /bl alias list, /bl alias del `<name>`.
- **New:** Raid start/stop: a Start Raid / End Raid button records everyone in the raid as an attendee (players invited later are added automatically) and runs a raid timer (HH:MM:SS, with attendee count) at the bottom of the SR window. The raid keeps running across /reload and relog.
- **New:** Ending a raid asks twice: "Do you really want to end the raid?" and then "Raise SR+ for all raiders?". On yes, every SR of an attendee that was not won gets +1 SR+, whether or not the item dropped; players who were not present get nothing. Duration, attendees and the result of the last 50 raids are saved.
- **Changed:** SR+ is no longer raised automatically after a lost roll (single rolls and multi-winner rolls). SR+ is now a reward for raid attendance only (see End Raid).
- **New:** Collapsible side menu on the right of the SR window (toggle arrow at the window edge, state is remembered). Export, Import, Save Raid, Load Raid, Options and LFM moved into the menu together with the Start/End Raid button; Lock, ML/GL and Loot Window stay in the main window, and the list moved up one row.
- **New:** Statistics tab in the options window: overview (raids, total and average duration, average attendees, items by MS/OS/TM/Raid Roll/Manual), raid list, loot ranking (top 10), attendance with bars, highest SR+ (top 10) and a per-raider detail view (raids attended x of y, items received split into MS/OS/TM plus Raid Roll/Manual, and which raids the player took part in). Duration and attendance are only available for raids recorded with Start Raid; loot log entries now carry an exact timestamp.
- **New:** Optional Round Robin for Main Spec (Options > Automation, default off, active only while a raid is running). Every item won through an MS roll (without SR) raises the winner's RR level for this raid. In MS rolls the lower RR always wins; the roll only decides between equal RR levels. Off-spec and transmog still rank below every MS roll. SR items, manual awards and Raid Rolls are unaffected. The raid is the round: ending the raid resets everything. Not-counted rolls are listed transparently (short line in raid/group chat with names and RR, full detail with rolls in your local chat, and "[RR n | x not counted]" in the loot window). Commands: /bl rr, /bl rr reset.
- **New:** Roll-sync popup shows Round Robin: the loot master sends the RR level with each MS roll (optional extra field in the RU message, ignored by older versions). The list is sorted by RR, shows "RR n" behind the roll and greys out not-counted rolls with a red X plus a legend.
- **Fixed:** Overlapping text in the Network tab of the options window: the Roll Sync hint wrapped over several lines and ran into the checkboxes below it. The controls are now anchored below each other and the tab is taller. The options tab bar now fits three buttons per row (Display & Sound, Management, Statistics) and the General and Automation tabs got more height.
- **New:** Test mode ("Start test run" in Options > Management): simulates a complete loot drop on the REAL engine with 10 made-up Naxxramas loot slots and 10 made-up raiders who roll, chat and emote. Everything is announced locally only (marked [TEST]) and your real data is backed up and restored automatically. (Carried over from the unreleased v3.33.)
- **Improved:** LFM text box is now multi-line with automatic wrapping and smaller font, and the window is larger. A line break pasted by accident is smoothed to a space when saving, so the posted text stays a single line. (Carried over from the unreleased v3.33.)
- **New:** Raid lead window (Options > Management > Raid lead window, or /bl rl): one tab per raid (General fallback, MC, Onyxia, BWL, ZG, AQ20, AQ40, Naxx, Timbermaw Hold, Lower Karazhan Halls, Tower of Karazhan, Emerald Sanctum, World Bosses). Per raid you can edit a welcome message, trash notes and a closing message, and per boss two announcement texts (255 characters each, with counter) plus an on/off checkbox. Default texts are included for all raids with custom content (Molten Core, Onyxia, BWL, Timbermaw Hold, Lower Karazhan Halls, Tower of Karazhan, Emerald Sanctum, the custom world bosses) as well as AQ20 and AQ40; vanilla bosses without custom mechanics start empty. Every boss also has "Send 1" and "Send 2" buttons for manual posting.
- **New:** Automatic announcements: on Start Raid the welcome message and trash notes are posted to raid/party chat (the raid is detected from the instance name, with the General tab as fallback); on End Raid the closing message is posted. When a boss is targeted for the first time, its message 1 is posted; message 2 goes out via the "Send 2" button or automatically after a configurable delay. The whole feature has a master switch (Options > Management, default off); when off, the window is locked and nothing is announced. Posting is throttled to one line per 1.2 seconds.
- **New:** Double-post protection for announcements: only the raid leader sends, or - if a name is entered in the sender field - only the player with exactly that name (e.g. an assistant). Each boss is announced only once per raid, other BananaLoot clients are informed via an addon message so they do not post it again, and a leader without a sender entry has priority over a configured sender. /bl rl reset clears the markers.
- **Changed:** Boss names are now a single source: BananaLootBossData.lua feeds both the raid lead announcements and the Auto Master Loot detection. The Anubisath Defender only counts as a boss inside Ruins of Ahn'Qiraj (it also appears as trash in AQ40).
- **Fixed:** Auto Master Loot did not recognise several bosses: Gehennas (Molten Core), the Edge of Madness bosses (Gri'lek, Hazza'rah, Renataki, Wushoolay), Captain Tuubid, Captain Drenn, Anubisath Defender, Master Blacksmith Rolfen, Emperor Vek'lor/Vek'nilash, and the world bosses (Azuregos, Lord Kazzak, the four Emerald Dragons, Dark Reaver of Karazhan, Concavius, Ostarius, Nerubian Overseer, Cla'ckora, Father Lycan), plus the revised names of Timbermaw Hold (Ormanos the Cracked, Loktanag the Vile, Selenaxx Foulheart, Ursol; Kodiak and Rotgrowl are one encounter) and Tower of Karazhan (Keeper Gnarlmoon, Ley-Watcher Incantigos, Echo of Medivh). Zone and boss names of the custom raids and the new world bosses are not verified in game.
- **Technical:** New files: BananaLootAlias.lua, BananaLootRaid.lua, BananaLootStats.lua, BananaLootRaidlead.lua and BananaLootBossData.lua (all listed in the .toc). BananaLootItemDB.lua is regenerated from the new data source. New SavedVariables fields: aliases, raidSession, raidHistory and a few settings; existing data is preserved.
